## 0. Status

Placeholder for the wall-clock targets below. **Superseded in part by
`design/acpi/perf-methodology.md`** (R30.M9-003, #1087), which records
what is actually measured and gated today and why the millisecond form of
every target in §1 is currently unmeasurable.

The short version: **this process has no clock**, and there is no thread
affinity or core reservation in the scheduler. Every figure in §1 is
therefore still **aspirational and unmeasured** — none of them has been
observed, on any machine. What *is* gated on every push is a
deterministic budget in **work** (fuel steps, peak evaluation depth, peak
frame index); see `perf-methodology.md` §2. The plumbing that would make
§1 measurable is filed as its own issue and summarised in
`perf-methodology.md` §4.

Treat the table below as a statement of intent, not as a baseline.

---

## 1. Aspirational targets (from `acpica-bubble.md` §11)

| Operation | Target |
|---|---|
| `AcpiOsGetTimer` | ≤ 50 ns |
| OSL MMIO read/write | ≤ 200 ns |
| Simple AML method evaluation | ≤ 50 µs |
| Complex AML method (boot) | ≤ 100 ms |
| Sleep state entry | ≤ 500 ms |
| SCI dispatch latency | ≤ 50 µs |
| PCIe hot-plug notification | ≤ 100 ms |
| Bubble restart after crash | ≤ 1 s |

## 2. What is measured today

is reproduced here for convenience; it is generated by `aml_fuzz budget`
and gated by `tools/verify-aml-fuzz.sh` on every push.

| `named` | 2 | 2 | 1 |
| `branch` | 8 | 4 | 1 |
| `package` | 6 | 3 | 1 |
